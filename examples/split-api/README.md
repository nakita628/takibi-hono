# Split API

An API generated by takibi-hono with `split: true`, to see what the option does.

## What `split` changes

[`openapi.yaml`](./openapi.yaml) has three first path segments: `/health`, `/users` and `/posts`. With `split: true` (see [`takibi-hono.config.ts`](./takibi-hono.config.ts)), each is a group:

- The app entry, [`src/index.ts`](./src/index.ts), exports each group under its name (`health`, `posts`, `users`) instead of one `api`. Every group is still registered on the one app.
- The client, [`src/client.ts`](./src/client.ts), is one client per group (`healthClient`, `postsClient`, `usersClient`). Each is typed by the routes of its group alone, so a caller of `usersClient` has TypeScript work out the users routes and not the whole app's.
- rpc, [`src/rpc.ts`](./src/rpc.ts), calls the client of each operation's group (`usersClient.users.$get`).

The handler bodies in `src/handlers` and the in-memory data in [`src/store.ts`](./src/store.ts) are written by hand; regenerating keeps them.

## Try it

```bash
pnpm generate  # regenerate from openapi.yaml, keeping the handler bodies
pnpm dev       # serve the app at http://localhost:5173/api
pnpm check     # type-check, including src/groups.ts
pnpm test      # call rpc through every group's client
```

```bash
curl http://localhost:5173/api/health
curl http://localhost:5173/api/users/1
```

## How it is checked

- [`src/groups.ts`](./src/groups.ts) asserts with `@ts-expect-error` that a group's client has no other group's routes (`usersClient.posts` does not exist). `pnpm check` fails if one of them ever does.
- [`src/split.test.ts`](./src/split.test.ts) calls rpc through each group's client, with `fetch` replaced by the app's own `request`. Every call reaches the one app, and its validators answer `400` for an invalid `userId`.
